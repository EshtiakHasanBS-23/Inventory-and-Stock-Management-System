## Overview

**Purpose:** Sign in with phone number and password so every action is recorded under the right name.
**User situation:** Karim is at the warehouse door with his phone.
**Entry:** Any signed-in address while signed out (the address is remembered); after "Sign out"; after a session ended; "Sign in" link on Sign up.
**Exit:** Success → the page first asked for, otherwise `/dashboard`. "Create one" → `/signup`.

## Layout

- **Desktop:** public layout, centred card: heading, optional session-ended line, form, switch link.
- **Phone:** the same card at full width; the phone keypad opens for the phone field (`inputmode="tel"`).

## Elements

| # | Element | Copy | testid | Behaviour |
|---|---|---|---|---|
| 1 | Heading (h1) | "Sign in" | – | |
| 2 | Session-ended line | "Your session ended. Sign in again." | `signin-session-ended` | Shown when the session ended (12 hours after last use, deactivation, or a password change elsewhere); hidden once a refusal shows |

| 6 | Show / Hide | "Show" / "Hide" (name "Show password") | `signin-password-input-toggle` | `aria-pressed` |
| 7 | Submit | "Sign in" | `signin-submit-button` | Primary, busy spinner |
| 8 | Switch link | "New business? **Create one**" | `signin-signup-link` | → `/signup` |

Form: `signin-form`. No field-level checks in the browser: everything goes to the server so a refusal never says which field was wrong.

## States

| State | What shows |
|---|---|
| Empty | Two empty boxes |
| Session ended | Session-ended line above the form |
| Signing in | Button spinner, "Saving…" for screen readers |
| Refused | Error summary with the refusal, focused; typed values kept |
| Success | Redirect (see Exit) |

## Refusal Messages

| Trigger | Message |
|---|---|
| Unknown phone, wrong password, badly formed phone, empty fields | "Sign-in details are not correct." |
| Correct password for a deactivated account | "This account is deactivated." |
| Network or server failure | "Couldn't save. Try again." |

The server makes failed sign-ins take the same time whether or not the phone exists.

## Signing out (shared frame)

"Sign out" (`app-bar-sign-out-button`) in the app bar ends the session on the server at once and returns to this page without the session-ended line.

## Accessibility

- Visible labels; the error summary is focused and read once per attempt.
- The skip link "Skip to content" is the first focusable element.

## API

| Call | When | Result |
|---|---|---|
| `POST /api/v1/auth/signin` `{phone, password}` | Submit | 200 + session cookie (HttpOnly, SameSite=Lax) and CSRF token; 401 `INVALID_CREDENTIALS` or `ACCOUNT_DEACTIVATED` |
| `GET /api/v1/auth/me` | App start | Current person, or signed out |
| `POST /api/v1/auth/signout` | Sign out | Session ended |

## Stories and Requirements

US-02 · FR-2, NFR-1, NFR-6 (sign-in ≤ 2 s; `/auth/me` well under 200 ms).
