## Overview

**Purpose:** Create a business and its first person, the Owner, and sign in at once.
**User situation:** Haque has no account yet. He wants to start with as little typing as possible.
**Entry:** "Create one" link on Sign in; typing `/signup`.
**Exit:** Success → signed in, lands on Dashboard (`/dashboard`). "Sign in" link → `/signin`.

## Layout

- **Desktop:** public layout without app bar or menu. A centred card (`auth-card`) with heading, form and the switch link below it. The skip link is in the header.
- **Phone (320 px and up):** the same card at full width with the phone gutter; fields stack in one column (they always do on this page).

## Field rules (from `packages/contracts`)

| Field | Rule |
|---|---|
| Business name | 1–100 characters after trimming |
| Your name | 1–100 characters after trimming |
| Phone number | 6–15 digits after removing spaces and dashes; unique across all businesses |
| Password | 8–128 characters (stored with Argon2id) |

## States

| State | What shows |
|---|---|
| Empty | Four empty boxes, hints visible |
| Field left invalid | Each field is checked when the person leaves it; its message appears under the hint |
| Saving | Button spinner, "Saving…" for screen readers |
| Success | Session stored; the public layout redirects to `/dashboard` |
| Server failure | Summary: "Couldn't save. Try again." Typed values are kept |

## Validation and Refusal Messages

| Trigger | Message | Where |
|---|---|---|
| Business name empty or too long | "Enter your business name." | Under the field |
| Name empty or too long | "Enter your name." | Under the field |
| Phone not 6–15 digits | "Enter a phone number of 6 to 15 digits." | Under the field |
| Password too short or too long | "At least 8 characters." | Under the field |
| Phone already used (server `DUPLICATE`) | "This phone number is already registered" | Under Phone number; focus moves there |
| Two or more fields wrong on submit | "N fields need fixing:" with a link to each field | Error summary, focused |
| Exactly one field wrong on submit | (no summary) | Focus moves to that field |

## Accessibility

- Each input has a visible label; hint and error are linked with `aria-describedby`; `aria-invalid` on error.
- The error summary is focusable (`tabindex="-1"`) and is focused after each failed submit, so it is read once per attempt.
- Password toggle is a real button with `aria-pressed` and `aria-controls`.

## API

| Call | When | Result |
|---|---|---|
| `POST /api/v1/auth/signup` `{businessName, name, phone, password}` | Submit with no client errors | 201 + session (HttpOnly cookie, CSRF token); 400 `VALIDATION_FAILED` with `field`; 409 `DUPLICATE` with `field: "phone"` |
