## Overview

**Purpose:** Change your own password with your current one. Other devices signed in as you are signed out; this one stays signed in.
**User situation:** Karim replaces the password Haque told him with one only he knows.
**Entry:** Menu "My password" (last item).
**Exit:** Stays on the page.

## Layout

- **Desktop:** heading; saved message; a white panel with two password fields and the button.
- **Phone:** the same panel at full width.

## Elements

| # | Element | Copy | testid | Behaviour |
|---|---|---|---|---|
| 1 | Heading (h1) | "My password" | – | Section `account-page` |
| 2 | Saved message | "Password changed. Other phones signed in as you are signed out." | `account-saved` | Green box, `role="status"` |
| 3 | Error summary | form-level message | `account-error-summary` | Form `account-form` |
| 4 | Current password | label "Current password" | `account-current-input` (+ `-toggle` Show/Hide) | `autocomplete="current-password"` |
| 5 | New password | label "New password"; hint "At least 8 characters." | `account-new-input` (+ `-toggle`) | `autocomplete="new-password"` |
| 6 | Submit | "Change password" | `account-save-button` | Primary, busy spinner |

## Behaviour

- On success both fields clear and the saved message shows. The person stays signed in here; every other session of theirs ends.

## States

| State | What shows |
|---|---|
| Empty | Two empty password fields |
| Saving | Button spinner |
| Saved | Saved message; fields cleared |
| Refused | Message under the named field; typed values kept |

## Validation and Refusal Messages (`packages/contracts/src/staff.ts`)

| Trigger | Message | Where |
|---|---|---|
| Current password empty | "Enter your current password." | Under Current password |
| Current password wrong | "Your current password is not correct." | Under Current password |
| New password shorter than 8 or longer than 128 | "At least 8 characters." | Under New password |
| Other failure | "Couldn't save. Try again." | Error summary |

## Accessibility

- Both fields have visible labels and their own Show / Hide toggle (`aria-pressed`, accessible name "Show password").
- Errors are linked to their field with `aria-describedby`; the saved message is announced.

## API

| Call | When |
|---|---|
| `POST /api/v1/auth/password` `{currentPassword, newPassword}` | "Change password" |
