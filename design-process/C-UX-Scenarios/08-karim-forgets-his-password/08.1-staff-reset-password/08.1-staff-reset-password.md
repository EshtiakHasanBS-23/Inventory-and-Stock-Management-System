## Overview

**Purpose:** The Owner sets a new password for a staff member who forgot theirs. All of that person's sessions end, and they sign in with the new password.
**User situation:** Karim is locked out; Haque resets his password from the Staff page.
**Entry:** "Reset password" chip on a staff row (`staff-reset-<phone>`). Not offered on the Owner's own row ("That's you").
**Exit:** "Set password" → notice on the Staff page; "Cancel" → back to the add form.

## Layout

- **Desktop:** the reset panel takes the place of the "Add a staff member" panel at the top of the page; the team table stays below it.
- **Phone:** the same panel at full width, above the team cards.

## Behaviour

- On success the panel closes, the add form returns, and the notice shows.
- Every session Karim holds ends at once (any phone still signed in as him is sent back to Sign in on its next request).
- The Owner's own password is changed only on My password (08.2).

## States

| State | What shows |
|---|---|
| Panel closed | Add form, team table |
| Panel open | Reset panel instead of the add form |
| Saving | Button spinner |
| Done | Notice; add form back |
| Refused | Message under New password, or in the summary |

## Validation and Refusal Messages

| Trigger | Message | Where |
|---|---|---|
| Password shorter than 8 or longer than 128 characters | "At least 8 characters." | Under New password |
| Reset the Owner through the API | "Change your own password on the My password page." | Error summary |
| A non-Owner calls the API | "Only the owner can manage staff." | – |
| Other failure | "Couldn't save. Try again." | Error summary |

## Accessibility

- The reset chip's accessible name includes the person's name.
- The panel heading names whose password is being set, so the context is clear to a screen reader.
- The notice is announced (`role="status"`).

## API

| Call | When |

| `POST /api/v1/users/:id/password` `{newPassword}` | "Set password" |
