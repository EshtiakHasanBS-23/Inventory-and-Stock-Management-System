## Overview

**Purpose:** Enter what is on the shelf for one product. Any difference from the record is saved as a "Stock count" movement with the counter's name; a matching count saves nothing.
**User situation:** Rafiq counted 44 bags where the record has 46.
**Entry:** Menu "Stock count".
**Exit:** Stays on the page for the next product.

## Layout

- **Desktop:** heading and intro; result message; a white panel with Product, recorded line, Counted quantity, Note, "Save count".
- **Phone:** the same panel at full width, one column.

## Behaviour

- The server locks the product row, reads the recorded quantity, and compares it with the count in the same transaction, so a stock change at the same moment cannot slip between the read and the save.
- Difference below zero → "Stock count" movement **out** for the missing units; above zero → movement **in** for the extra units. The movement note is "Counted X, system had Y." (plus the person's note when given). Its value uses the current unit cost.
- Count movements cannot be reversed; a wrong count is corrected by counting again.
- After saving, the counted quantity and note clear; the product stays chosen.

## Accessibility

- The result is announced (`role="status"`); missing vs extra is stated in words, not only by the amber colour.
